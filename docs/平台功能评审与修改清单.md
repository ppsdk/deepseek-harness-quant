# 研究平台功能评审与修改清单

评审日期：2026-10-26。对象：本地项目当前工作区；包含回测报告、K线成交标记，以及第10节的整体验证与优化。

## 1. 结论

平台已经能走通“准备数据 → 编写因子 → 组成策略 → 选股保存名单 → 设置成本回测 → 比较实验”的流程，适合开展 A 股日线策略研究。现有覆盖面较广，但成交模拟、历史股票范围和数据时点仍有明显缺口，尚不足以把曲线直接当成真实可实现的收益。

下一轮应优先完善 A 股成交规则、历史数据和研究验证。多标的扩展应先建立统一的标的信息与市场规则，不能只给当前股票代码列表加几个美股或期货代码。

以下分数是首轮审查时的基线分数，本轮落地进展见第10节。它们是工程评审的主观分数，不是行业测评或投资评级。标准：5 分表示主要流程可用但有显著缺口；8 分表示日常使用完整，关键边界有验证；10 分需要长期、完整的运行与口径证据。

| 维度 | 当前判断 | 主要依据 |
| --- | --- | --- |
| 功能覆盖 | 7/10 | 目录实测有 183 个因子、40 套策略、10 类模型；选股、公式、回测、择时、股票池、论文与 AI 已有独立入口；目录数量不等于每项都有完整数据或已验证有效 |
| 回测可信度 | 4/10 | 有前收盘信号、次日开盘与费用账本；仍用小数调整份额，缺完整涨跌停、历史税率与公司行为处理，开盘过滤使用当日完整行情 |
| A 股适配 | 5/10 | 有沪深北代码、成交量、ST 字段、最低佣金与卖出税；各板块/日期生效的规则、可卖数量和历史股票范围仍需完善 |
| 研究严谨性 | 5.5/10 | 有因子分组、排序相关性、覆盖率、按日期训练与训练截止记录；缺行业/市值影响剔除、统计置信度、固定独立检验区间与大量调参后的防误判措施 |
| 多市场扩展 | 4/10 | 数据接口和配置目录可以复用；代码校验、复权方式、货币、交易日和撮合仍主要围绕 A 股日线 |

## 2. 参考软件各取什么

三类工具解决的问题不同，不宜照搬整套界面，也不能假设采用某个引擎就自动符合 A 股规则。

| 参考对象 | 本平台应借鉴的能力 | 当前对应能力与差距 |
| --- | --- | --- |
| 通达信 | 股票搜索、自选股、条件选股、公式使用、价格/成交量/技术指标同屏，尽量缩短查看一只股票的路径 | 已支持代码/名称匹配、股票池、公式和指标叠加；尚无通达信公式兼容层、完整画线工具与统一选股预警中心 |
| TradingView 风格的图表体验 | 拖动缩放、十字光标、多图/副图联动、保存布局，在价格图上解释策略何时买卖 | 已有拖动缩放、尺寸调整与副图；本轮加入真实回测买卖标记；多图同步、画线、布局模板仍待开发。没有声称本项目可运行 Pine Script |
| Backtrader | 明确订单与成交生命周期、可插拔费用和滑点、成交量约束、多数据源、独立分析器 | 当前是本项目自己的现金持仓账本，没有接入 Backtrader 执行器；限价/止损/部分成交/撤单等需要进一步建模 |
| 因子研究工具的常见流程 | 先检查字段和股票范围，再做分组、稳定性和扣费检验 | 已有单因子检验与公式管理；还需要因子相关矩阵、行业/市值控制、可交易分组组合和组合归因 |

通达信、Backtrader 的下列官方资料本次可以访问。TradingView 策略文档本次连接超时，不能据此宣称已逐项核验其当前商业版本；这里只把它作为用户指定的交互参考。其官方 Lightweight Charts 仓库曾成功读取，它是图表库，不等同于 Pine 执行器或 Strategy Tester。

- [通达信下载中心与功能说明](https://www.tdx.com.cn/soft.html)：页面明确提及公式、历史竞价图、动态行情筛选、多周期多指标调用；本次没有安装商业客户端实测。
- [Backtrader 订单说明](https://www.backtrader.com/docu/order/)：订单类型、状态及交易通知。
- [Backtrader 分析器](https://www.backtrader.com/docu/analyzers-reference/)：回撤、收益、夏普、交易统计等。
- [Backtrader 滑点](https://www.backtrader.com/docu/slippage/slippage/) 与 [成交量约束](https://www.backtrader.com/docu/filler/)：成交价格与可成交数量应分别建模。
- [TradingView 官方图表库](https://github.com/tradingview/lightweight-charts)；[Pine 策略文档](https://www.tradingview.com/pine-script-docs/concepts/strategies/) 为待重新核验来源。
- A 股规则实施前应核对 [上交所规则](https://www.sse.com.cn/lawandrules/sselawsrules/trade/universal/)、[深交所规则](https://www.szse.cn/lawrules/rule/trade/) 及北交所适用版本；本轮未完成全部市场的生效日期与例外条款核验。

## 4. 必须优先修正：影响回测结论

下表记录原始问题；本轮处理状态见第10节。未完成的交易口径不能用添加图表替代。P0 表示会影响收益是否可信；P1 表示主要研究能力与日常体验；P2 表示扩展能力。

| 编号 | 优先级 | 问题与影响 | 建议修改 | 验收条件 |
| --- | --- | --- | --- | --- |
| R01 | P0 | 开盘 `tradable()` 读取成交日的最高、最低、收盘和全天成交量，使用了开盘时还不知道的完整日线 | 把开盘时可知信息、真实开盘撮合规则与日线保守估计分开；如果缺必要信息则明确该次实验口径 | 保持开盘与开盘前状态不变、仅改变当天后续高低收/全天量，不得改变“开盘已成交”的记录；另有涨跌停/停牌情形测试 |
| R02 | P0 | 用前复权价格和小数份额，未完整模拟真实交易单位、最小报价与可卖数量 | 引入按市场和生效日期读取的交易规则，保存持仓批次与可卖数量 | 普通股票、不同板块、ST、上市特殊日期等有合成案例；非法数量/价格不成交，现金和可卖数量守恒；具体制度以交易所文件核验 |
| R03 | P0 | 一字行情一律禁买卖，不能等同于精确涨跌停撮合；无成交量参与率、部分成交 | 加入涨跌停价格/参考价、方向相关成交限制、量约束与剩余订单记录 | 涨停买入、跌停卖出、可成交方向、停牌、量不足分别有明确结果；不能因一根日线有多个价格就认定开盘必能成交 |
| R04 | P0 | 当前缓存股票范围可能缺退市股；未指定名单时按代码排序截前 N，并不代表全 A 股或随机代表样本 | 保存历史上市/退市、ST、成分股和行业记录；提供“当时可交易范围”，显示每天实际覆盖数 | 某日期上市前股票不进入；退市股票不会从早期历史消失；已知缺失明确显示，不把下载完成数等同完整历史覆盖 |
| R05 | P0 | 财务通道有可用日期保护，但今天获取的财报不能支撑过去年度的全部基本面研究；历史估值和股息率覆盖仍有限 | 按当时可获得日期保存报表版本、财务口径和估值序列；保留缺值与来源 | 修改未来才可用的财报，不改变之前选股；修订版本不能覆盖当年已知版本；逐策略展示所需字段在每年的覆盖率 |
| R06 | P0 | 分红送转、复权与真实股数/现金流没有统一，旧实验与更新后的图表可能不同 | 分开信号用调整价格和交易用原始价格；公司行为进持仓账本；归档价格快照/版本 | 现金分红、送转、除权等案例中资产连续且不重复计收益；买卖点按归档成交解释；可定位原始数据版本 |
| R07 | P0 | 税率固定，缺过户费、历史分段和不同标的的费用；高换手策略受影响更大 | 费用按日期、市场、品种和方向配置；区分佣金、税费、价差和冲击 | 同样金额在费率切换前后按正确表计费；最低佣金与整手、部分成交一起核算；无重复滑点扣费 |
| R08 | P0 | “观察/无效”主要由年化正负给出，不能表示完成可信度或统计有效性验收 | 分开显示“数据/成交规则核验结果”“历史表现”“独立区间检验结果” | 存在前视或关键数据缺口时，即使收益很高也不能显示已验证；负收益不自动等于因子永远无效 |

代码证据主要在 `backtest/research_runner.py`：`load_panels()`、`build_result()`；仓位账本与 `tradable()` 现位于 `backtest/research_portfolio.py`。不应仅把限制写进说明而长期不修撮合与数据。

## 6. 多标的扩展方案

建议按“股票/ETF → 港美股 → 期货/期权”逐类实现，每一类都独立验收。

| 层次 | 当前边界 | 应建立的能力 |
| --- | --- | --- |
| 标的资料 | 多处要求六位沪深北股票代码 | 稳定标的ID、市场、品种、币种、时区、上市退市日、最小报价、交易单位；ETF与指数不能混作可交易股票 |
| 交易日 | 使用价格面板中的日期 | 各市场交易日、节假日、半日市和盘中时段；跨市场日期显示和订单时区明确 |
| 现金/持仓 | 单币种、小数调整份额 | 多币种现金、汇率、各类交收规则、融资/借券限制；ETF按品种规则处理，不统一假设全部T+0或T+1 |
| 撮合 | 日线开盘换仓 | 独立订单模型与品种适配器，支持拒绝、撤单、部分成交和有效期 |
| 衍生品 | 无完整保证金与合约生命周期 | 合约乘数、保证金、逐日结算、到期/换月；期权再增加到期行权与风险指标 |
| 数据 | 前复权A股面板 | 各品种数据适配器与统一字段单位，价格调整方法、交易数据和研究信号分层 |

不建议现在就把所有资产塞进同一个股票账本，或直接更换引擎并假定历史结果自然兼容。可以用合成案例与第二个引擎交叉核对关键规则，再决定是否引入 Backtrader 等执行后端。

### 已落实的仓位口径

- 调仓时先按总资产分配总股票预算，再限制单股比例；缺少候选或波动历史时未分配部分保留现金。单股上限之和小于总仓位上限时，也保留现金。
- 逆波动分配只用信号日之前已知的收益波动，波动越小预算越多；零波动或历史不足不填造数值。
- 止损以含买入佣金的成本价为基础；止盈同口径。移动止损以持仓后的最高有效收盘为基础，不把滑点后的买价当成最高收盘。
- 收盘触发后，下一交易日按实际开盘价加/减滑点尝试成交。跳空时不会假定按设定的止损价格成交；不能成交的个股退出请求继续保留；个股退出不微调其他股票。退出优先顺序是止损、止盈、移动止损、持有期。
- 退出后可暂停若干交易日买回；期间个股与组合市值仍随行情变化。仓位上限是调仓目标约束，价格波动、费用或无法卖出可能导致实际比例偏离，不能解释为时刻保证不超限。
- 预算使用本地前复权参考收盘，不包含委托费，不提供真实整手指令。实验仓位与原主观持仓分开，未修改真实账户。
