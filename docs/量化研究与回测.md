# 量化研究与回测

项目的主要用途是：准备 A 股数据、提出因子假设、运行带交易成本的回测、比较实验，并保留可检查的成交记录。研究回测可独立于 AI API、Pitch 推荐和远期池运行。

## 页面使用

导航现在直接展示独立页面，不再折叠到“更多”：

| 页面 | 用途 |
| --- | --- |
| `/factors` | 按分类查因子，创建/编辑公式，检查排序相关性、分组涨跌和覆盖率 |
| `/strategies` | 查看策略条件和缺失数据，阅读聚宽等原始参考，跳转修改或回测 |
| `/positions` | 查看所选实验的期末持仓、成本和盈亏，给自己的股票名单分配预算 |
| `/backtests` | 搜索实验、收藏与备注，选择2—4次回测比较真实日期上的净值与费用 |
| `/ml` | 决策树、随机森林、极端随机树、梯度提升树、组合模型，按日期滚动训练并回测 |
| `/data` | 名称或代码搜索、点击查看K线、手动更新股票日线/目录/指数/论文 |
| `/papers` | 搜索arXiv元数据、展开原始摘要、手动更新；不是已验证的投资结论 |
| `/timing` | 查看沪深300均线条件，并在研究或回测参数中明确选择后生效 |

K线图支持拖动前后、滚轮缩放、放大/缩小/还原、全屏，以及拖右下角调整尺寸。均线叠加价格图，RSI、MACD等显示在副图；同时显示项数由图表配置限制。股票输入框支持名称/代码部分匹配、方向键与回车。

自定义公式保存在 `config/research_factors.yaml`，可引用已有指标编号，例如 `roc_20 / (volatility_20 + 0.0001)`。公式解释器只运行白名单运算，不执行任意Python；拒绝未知引用和循环依赖。单因子检验比较信号后下一开盘与第h+1个开盘，分组收益未扣费，重叠区间样本也不独立。

机器学习的目标同样从下一开盘起计算。每次拟合只用收益结果在预测日前已结束的训练样本，不随机打乱训练/检验日期；每个日期的输入分别排名，不用未来全样本拟合标准化。训练窗口、指标、模型及每次训练截止日期都写入回测归档。最多300只股票；预置5项机器学习评分可加入普通因子策略，独立实验页允许调整训练设置。

手动更新只启动本次任务，不建立定时任务。股票下载使用工作区独占锁，正在下载时复用已有进程；Windows进程状态使用只读查询。论文、目录、指数更新失败会显示错误，论文抓取失败保留旧记录。计算任务共享互斥锁，服务重启后中断的任务会提示重新运行。

新增配置 `research_services`、`research_ml`、`research_references` 均有 `.yaml.example`，本地覆盖与自定义因子文件受更新脚本保护。股票与论文内容保存在本地缓存/输出目录，不能跟随代码包再分发行情。

参考来源：

- [聚宽官方策略与历史财务查询教程](https://www.joinquant.com/help/api/help?name=api)：加入MA5偏离阈值、正PE不超过10等改编例子。MA5示例简化为换股日重新筛选，不复制原教程在0—1%区间保持原仓的逻辑。
- [聚宽技术指标文档](https://www.joinquant.com/help/api/help?name=technicalanalysis)：MA、RSI、BOLL等技术条件；本地阈值与换股规则不代表官方推荐。
- [AlphaPurify](https://github.com/eliasswu/AlphaPurify)：参考因子目录、排序相关性与分组分析流程。未安装运行该项目，当前也未提供行业中性化或其完整归因功能。
- [Backtrader](https://github.com/mementum/backtrader)：参考均线交叉和指标预热，研究执行仍使用本项目现金持仓账本，没有迁移执行引擎。

首页 `/` 与 `/research` 为研究工作台，提供以下完整流程：

1. 在“添加 / 编辑策略”勾选指标，选择优先高值还是低值、重要程度及可选的数值上下限，填写策略编号、名称及默认选股数量和换股间隔，点击“保存策略”。也可以载入内置策略组合再用新 ID 另存。
2. 已保存策略立即进入研究与回测目录。自定义策略允许修改后覆盖保存；内置策略不能覆盖。保存使用版本检查，其他窗口已修改目录时会提示刷新。
3. 在“策略选股”选择策略、收盘截止日和缓存股票范围，运行候选排名。先检查每项指标的上下限，再把各项指标排个名，按重要程度合成分数。缺少任一指标值的股票不参与，已知 ST 和零成交量剔除。
4. 点击候选股的“行情”查看前复权蜡烛图与成交量。日期范围可调整，图表显示最近配置数量的日线，缺失交易日不补齐。悬停可查看开盘、最高、最低、收盘价和成交量；可勾选均线、RSI、MACD 等图表指标。
5. 点击“设置滑点并回测”，策略及选股范围会带入回测页，再设置研究起始日和成本。

选股排名与回测选股共用 `factor_score` / `rank_candidates`，无第二套推荐评分。截止日信号只能在下一交易日尝试成交；选股结果不写入持仓和买入指令。下载的选股 JSON 保留实际股票池、数据指纹、因子分项百分位和策略定义。

页面添加的是声明式因子组合，并非执行任意 Python 脚本。自定义公式可以在因子管理页添加；新的程序算法仍需通过代码扩展并验证。

成本回测步骤：

1. 双击 `启动.cmd`，打开 `http://127.0.0.1:8787/backtest`。
2. 选择策略，设置起止日期、初始资金、持仓上限、股票数上限和调仓间隔。
3. 设置双边佣金、最低佣金、卖出印花税及单边滑点，然后点击“运行回测”。
4. 查看可缩放的净值、回撤、新实验仓位、月度收益热图、年度收益和成本。成交表支持代码/方向筛选、分页与CSV导出；旧实验可在“回测管理”直接打开图形报告，没有逐日仓位的旧档案会明确说明。
5. 保持其他参数相同，将滑点从 0 改为 10、20 基点分别运行，在历史记录中比较结果。1 基点 = 0.01%，10 基点 = 0.1%。

结果中的“在K线上看策略买卖点”可以选择实际成交过的股票，同时查看成交量和附加技术指标。红色“买”在买入当日K线下方，绿色“卖”在卖出当日上方；悬停能看到信号日、成交日、归档成交价和数量。支持前后定位买卖点，并可带着实验编号跳到研究工作台；周/月线将成交标在所属K线上。未成交请求不会标成已买入。K线来自当前缓存，价格如有复权更新，以归档成交记录解释这次实验。

报告设置在 `config/backtest_report.yaml.example`，可复制为同名 `.yaml` 覆盖；通过API传给页面。后续开发优先级、A股成交缺口及多标的扩展建议见[平台功能评审与修改清单](平台功能评审与修改清单.md)。

策略目录从配置读取，新增均线趋势、均线金叉、MACD 金叉、RSI 超卖、布林下轨、放量突破、动量、低波动、Alpha101 示例，以及盈利质量、共同增长、低估值、高股息、低负债等基本面方法。缺数据的策略会标注“需补数据”，不会以估算值冒充真实数据。

## 参数和策略配置

运行时读取 `config/research.yaml`，缺失时使用同名 `.example` 模板。复制模板可更改参数默认值和范围、添加声明式因子组合；修改后重新加载页面即可读取。

页面添加的策略独立保存在 `config/research_strategies.yaml`（缺失时为空目录），不会改写内置模板。导航由 `config/navigation.yaml` 或其 `.example` 模板动态提供。两个本地配置均忽略于 Git 并受更新脚本保护。基础指标来自研究配置中的 `factor_catalog`；常用技术和基本面指标来自 `factor_library.yaml(.example)`，101 条公式来自 `alpha101.yaml(.example)`，新增预设策略来自 `research_presets.yaml(.example)`。本地覆盖文件均忽略于 Git，并受更新脚本保护。

策略的 `factor_list` 使用目录中的指标编号。`sign: -1` 表示优先低值，`weight` 表示重要程度，`min` 和 `max` 为原始指标值的上下限。未知因子、缺失字段和非法参数会明确报错，不会默默换成其他策略。

接口：

- `GET /api/research/config`：参数定义及策略目录。
- `POST /api/research/strategies`：保存自定义策略，带当前 `revision` 防止覆盖并发修改。
- `POST /api/research/screen`：收盘截止日选股，共用研究评分。
- `GET /api/research/chart?code=000001.SZ&start=2024-01-01&end=2025-12-31`：缓存前复权日线。
- `GET /api/research/fundamentals`：财务指标覆盖、可用日期和同步状态。
- `POST /api/research/fundamentals/sync`：通过 AKShare 获取指定季度财报，独立后台任务。
- `POST /api/research/fundamentals/import`：导入带可用日期的财务 CSV。
- `GET /api/navigation`：动态导航。
- `POST /api/research/run`：参数化实验，无网络行情调用。
- `GET /api/live/backtest_archive`：历史实验目录。

市场概览保留在 `/overview`；未生成沪深 300 月线择时或日报时显示明确空状态。没有配置并验证定时任务前，界面不承诺这些产物会在某个时刻自动生成。

Python 示例：

```python
from backtest.bt_runner import run_backtest

result = run_backtest(
    strategy="reversal20", topn=5, stocks=100,
    start="2024-01-01", end="2025-12-31",
    initial_capital=1_000_000, rebalance_days=20,
    commission_bps=2.6, min_commission=5,
    stamp_tax_bps=5, slippage_bps=10,
)
print(result["metrics"], result["costs"])
```

指定股票时传入 `codes="000001.SZ,600519.SH"` 并相应设置 `topn`。代码必须已经下载到本地，股票数上限必须不小于指定数量。

## 当前成交口径

- 信号使用前一交易日收盘可见的数据，在下一交易日开盘执行。调仓周期按回测区间内交易日计数。
- 持仓份额持续保留；调仓只交易目标份额与已有份额的差额。佣金和最低收费按每笔成交收取，印花税只在卖出时收取。买入滑点提高成交价，卖出滑点降低成交价。
- 缺失、停牌、零成交量或一字行情禁止成交。未完成的订单取消，下一次调仓重新计算。过滤一字行情是日线撮合近似，不表示已精确重建所有板块的涨跌停制度。
- 已知历史 ST 不参与选股；未知 ST 不假装已排除。换手因子拒绝 2019 年以前的研究窗口。
- 下载未完成也可对已经缓存的股票运行；默认按代码排序截取，界面和结果记录实际代码列表。完整代码池仍需自行检查下载覆盖及幸存者偏差。
- 价格为前复权，份额为可分割的调整份额，不模拟真实 100 股整手、原始价分红现金流、过户费、盘口冲击或成交量参与率。已有持仓在缺行情时沿用最后估值，并记录陈旧估值天数；不填充可成交行情，不在期末强制平仓。
- 印花税使用用户指定固定费率，不自动按历史分段。2019 年至 2023 年部分区间的实际税率高于当前默认值，跨期研究需单独评估。
- 全池等权曲线是未计成本的参考收益，不是可交易指数。当前数据边界未消除前，正收益实验最多标注“观察”，不能直接宣称策略有效。

实验保存在 `output/backtest_archive/research_<strategy>_<run_id>.json`，包含实际参数、策略定义、数据指纹、净值、费用、完整成交及拒单记录。运行结果属于本地研究产物，不应随代码包再分发行情数据。


## 常用指标和策略条件

研究页可按分类、名称或编号搜索，勾选“只看已选”可检查自己的组合。33 项技术指标包括均线及偏离、均线金叉、MACD、RSI、KDJ、布林带、ATR、ADX、CCI、威廉指标、均量比、涨跌幅、突破、MFI、CMF、OBV 量价差和波动率。加上原有 7 项基础指标、12 项基本面指标和 Alpha101，共 153 项；另增加 5 项机器学习评分，共 158 项内置指标。自定义公式另计。

策略不是只换了名字。例如：

- RSI 超卖：RSI 14 的上限为 30，低值优先。
- 均线金叉：5 日均线上穿 20 日均线的事件值下限为 1，只选当天刚上穿。
- 放量突破：收盘价达到或超过此前 20 日最高价，且 5 日均量 / 20 日均量至少为 1.2。
- 收入和利润共同增长：两项同比增长下限都为 10，表示都至少增长 10%。

上下限按原始值检查。把两项条件的重要程度设为 2 和 1，表示前者在综合分数中的比重为后者两倍。条件越严格，可能选不够设定数量；系统不会拿不符合条件的股票补足。

RSI、ATR、ADX 使用 Wilder 平滑，先用完整窗口的简单平均初始化；RSI 单边上涨为 100、单边下跌为 0、完全不变为 50。MACD 使用 EMA 12/26/9，柱为 2×(DIF-DEA)。KDJ 为 9 日 RSV、平滑参数 3，首个有效 RSV 初始化；CCI 使用同一个窗口内典型价格的平均绝对偏差。布林带用 20 日均值和总体标准差的两倍。所有计算使用实际高低价，缺字段不会用收盘价估算。图表中缺值留空，不跨缺值连线。

## 基本面数据：可用日期很重要

“基本面数据”支持 AKShare 获取财报和 CSV 导入。AKShare `stock_yjbb_em` 返回东方财富当前版本的报表及“最新公告日期”；来源还包含新三板等公司，因此同步结果只保留本机 A 股股票目录中的代码。需要先取得 A 股目录。

当前能直接获取的字段有：每股收益、营收同比增长、净利润同比增长、每股净资产、ROE、每股经营现金流、毛利率。市盈率、PB、股息率、负债率和历史总市值的通道已支持 CSV，但不会用不存在的数据计算。ROE、增长率、毛利率、负债率及股息率均用百分点，填 10 表示 10%。每股指标为元，市值为元。

最新版本的旧报表，可能已经修订。为了不把后来的修订带回过去，新抓的报表以“公告日次日”和“抓取日次日”中更晚者作为可用日期。因此，今天获取的 2026 年中报不能用于检验 2019 年策略。选股仍按最后有行情的日期检查；在下一有行情日到来前，新财报可能暂时无法与价格一起使用。

历史回测可导入历史版本 CSV：

```csv
code,metric,value,available_date,report_date,source
000001.SZ,roe,10,2024-04-02,2023-12-31,synthetic-example
```

上面是合成格式示例，不代表该公司的真实指标。导入者需确认 available_date 是这些数值当时已可获得的日期，而不是报告期。数据在 `data/cache/research_fundamentals.db` 保存，同代码、指标、可用日期及报告期的重复键保留首次记录；修订请使用新的可用日期。迟到的旧报告不能覆盖已经可用的新报告。

报告期距选股日超过 550 天的普通财务指标不再使用。历史市值、PE、PB 只在记录对应日期使用，不把一天的估值延续到以后；股息率默认最多延续 31 天。这些规则可在配置中调整。财报报告期累计 EPS、现金流和年度指标不能不加区分混用，跨行业 ROE 和负债率也需自行控制。

## Alpha101：已实现公式，收益需要重新验证

公式来源为 Kakushadze《101 Formulaic Alphas》[原论文](https://arxiv.org/abs/1601.00991)附录 A。全部 101 条公式可查看，使用受限解释器计算，不执行任意 Python。当前缓存仅有前复权日线：52 条所需字段可直接提供；49 条需要额外的成交均价、历史市值或当时行业分类。实际可用数量会随数据改变，以 API 说明为准。

实现约定：

- rank 使用平均名次除以当天有效股票数；ts_rank 为窗口中最后值的归一化名次。并列值取平均名次。
- 小数窗口向下取整；时间窗口需完整数据。标准差及协方差按样本口径（ddof=1）。
- ts_argmax/ts_argmin 最早一天编号为 1、最新一天为窗口长度；并列极值取最早者。decay_linear 越近权重越大。
- adv 按原论文的 average daily dollar volume 使用平均成交额，单位是元。它不是平均成交股数。
- SignedPower 为 sign(x)×abs(x)^a，普通 ^ 为普通幂。分母为零、无效对数及缺失输入保留空值；比较和三元表达式也不把空值当成 false。
- VWAP 不直接用成交额 / 成交量与前复权价格混算。取得同一天不复权收盘后，乘以前复权收盘 / 不复权收盘的比例；没有这些字段时明确禁止计算。行业内比较需要当时的分类，当前未接入历史行业分类。
- 本框架统一下一交易日开盘执行，包括原论文按当天收盘交易的第 42、48、53、54 号。股票池、币种、成交约束和费用也不同，不能据此宣称复现论文收益。

验证包括 101 条公式全部解析与计算、增加未来数据不改变历史结果、简单公式独立核对、技术指标边界、筛选上下限、财报可用日期及不可覆盖旧版本等。合成数据测试证明程序规则，不证明投资收益。


## 保存选股结果，再交给策略回测

1. 在研究台选择策略和选股日期，运行选股。点击“保存这次选股为股票池”，保存的是结果表里实际选中的代码，不是原来的输入范围。
2. 打开“保存的股票池”，可以查看代码、下载每行一个代码的TXT，并选择原策略或另一套策略进入回测。
3. 回测页会填入对应代码、调整股票数和持仓上限。设置日期、换股间隔、佣金和滑点后运行。切换策略仍使用这份股票池；清空股票池选择后可改为手填范围。
4. 股票池带有选股日期，回测开始日必须晚于该日。例如2024-06-03收盘选出的名单，最早从2024-06-04开始检验，不能拿它回测2019年。要做历史实验，请先按当时日期选股。按最新行情选出的名单，需要后续交易日的数据才能检验。

保存的数据位于本机 `data/cache/research_stock_pools.db`。每次保存产生一份新名单，包含名称、选股日、来源参数和代码哈希；回测归档同时保存股票池快照。固定名单不等于随时间换股的全市场策略，也不能解决退市股票遗漏的问题。手动保存名单时可填写确定日期；不填写时由使用者核对名单在历史上是否已知。

高斯滤波只使用当天和此前价格，默认用21根日线做单边加权，上下轨为平滑线加减2倍ATR。它会有滞后，不使用读取未来价格的居中滤波。威科夫提供的是明确条件的事件识别，不据此自动推断主力完整的吸筹或派发阶段。“量价时空”在这里具体指价格箱体、成交量、收窄时长与距支撑的ATR距离，未声称复现某个流派的全部方法。

道氏和RSI背离默认等待右侧2根K线完成才确认，信号标在确认日，同时注明拐点形成日；背离对照线也只有确认之后才展示。道氏周/月结构只从已结束的自然周期取得；遇周末或休市，完成后的状态从下一个可用交易日显示。日/周/月高低点分别计算。普通技术指标随当前K线周期计算，这些形态组合始终先在日线识别，再将确认记录归到显示的周/月K线上；背离两端的连线用于日线对照。

图上空心三角表示看多/看空事件，灰色菱形表示拐点确认；默认不铺满文字，可开启“显示信号文字”或将鼠标移到标记上查看。道氏日、周、月状态分别显示，便于对照。实心“买/卖”表示所选回测实际成交。可用“上个/下个识别信号”或点击识别记录中的日期定位K线。识别记录说明触发条件，RSI背离还列出两次RSI读数。研究信号不等于成交：回测在下一交易日开盘尝试执行，仍受持仓数、排序、停牌、一字行情、佣金及滑点约束。每套模板有最长持有期，超过后退出候选；日周月一致模板则按当时三种趋势持续筛选。默认均为只做多，不将看空事件变成A股融券卖空。

配置位于 `config/research_patterns.yaml.example`，可复制为同名 `.yaml` 调整窗口、阈值、最长持有期、显示线和策略组合。回测归档会保留实际使用的形态参数；查看该回测的K线时用其参数快照重算这些形态，价格仍来自当前本地缓存。技术检验使用合成数据覆盖单边平滑、拐点延迟、未完成周/月、缺字段和次日成交，不能据此认定策略有效或预测胜率。

## 市场择时工作台

可选择观察指数、查看均线、MACD、RSI、波动上限、回撤上限、RSRS或组合规则。RSRS使用高价对低价回归斜率，做历史标准化并乘以拟合优度，以进入/退出双阈值保持中间状态；需要完整预热历史，不用未来数据补足。

“每日检查风险”在前一收盘不满足时，于下一交易日开盘尝试退出；一字行情、停牌等无法卖出时记录拒绝，并在风险仍不满足时继续尝试。信号恢复后要等策略换股日才买入。“只在换股日检查”保留原来的模式。两种模式均不假设当天收盘信号可以在当天开盘执行。

工作台可以在同一份股票行情上运行有/无择时两次回测，比较收益、回撤、成交笔数和费用，两份结果分别归档。图中的1表示允许持有、0表示要求退出；它只是市场条件，具体持仓还取决于选股与能否成交。查看历史信号不会自动改仓。

## 工作台市场观察

- A股恐慌观察采用沪深300ETF期权 QVIX（期权论坛、AKShare同源），不是覆盖全A股的官方VIX。沪深300股指QVIX近期有效历史较旧，因此默认使用仍更新的ETF口径。纳斯达克恐慌使用Cboe官方VXN，对应纳斯达克100期权约30天年化隐含波动率，不是标普500的VIX。二者原值单位为百分数，另列各自在近756期的历史百分位。
- 板块热力图覆盖配置中的10个中证行业指数。温度 = 20日涨幅历史百分位×40% + 252日回撤历史百分位×30% + 20日年化波动率的反向历史百分位×30%。百分位取自身近756期有效观测，至少120期；相同值按中间名次。高温表示近期走势更强、更平稳，不等于便宜。市场压力 = 100 − 同日行业温度均值，至少覆盖80%的配置行业才显示。它是自定义走势评分，和期权QVIX分开展示。
- 红利低波默认观察中证红利低波100指数（930955）。总分 = 股债利差得分×50% + 回撤位置得分×25% + 低波动得分×25%。股债利差为计算用股本股息率减中国10年国债收益率，以−1到5个百分点线性映射到0到100分。回撤位置以距252个交易日最高收盘的跌幅计算，0到30%映射到0到100分；低波动得分为20日年化历史波动率在近756期的反向百分位。结果不是预期收益，更深回撤也可能是风险恶化。所有权重、窗口和映射端点均可配置。

### 按历史区间理解当前读数

工作台的“这些读数之后，历史上更容易涨还是跌？”提供四项指标的横向表，并可逐项查看分区间统计。市场压力与红利性价比按百分制区间分组；QVIX和VXN按各自隐含波动率原值分组，不能把VXN的30%误当成30分。区间、观察期、门槛和最少次数均在 `market_dashboard` 的 `interpretation` 配置中。

默认分别观察后5、20、60个交易日，期末大涨/大跌门槛分别为3%、5%、10%。信号收盘后，使用下一实际交易日开盘价进入，在持有N个交易日后的下一开盘价退出；不使用信号当天开盘，不统计尚未到期的样本。除期末涨跌外，还列出期间相对进入价曾下探到跌幅门槛的比例，避免把先大跌后收复的情况当作没有风险。它不是从期间高点开始计算的最大回撤。

每个区间内按照日期顺序保留互不重叠的持有区间，并列出原始信号天数和实际观察次数。表内提供平均及中位数涨跌、大涨/大跌次数与比例、期间下探比例，以及所有区间的对应市场基准。另取可用分数历史最后30%的日期单独复核。分组至少12次、后段至少6次，且同一方向的大涨或大跌比例在全段与后段均高于各自基准至少5个百分点，才提示历史上“偏多”；这只是描述规则，不是显著性检验、最优阈值搜索或未来概率承诺。未扣费用，不含分红，不等于可交易策略的收益。

市场压力、QVIX与沪深300配对，VXN与新增的纳斯达克100指数日线配对；三指数价格对比图仍使用纳斯达克综合。红利性价比与其本身的红利低波100指数配对。各项历史长度可能不同，跨市场的比例不能直接当成同等风险。

红利低波的当前估值文件只有约一个月的股息率，而且没有历史公布时刻。新增取得的股息率仅从本机首次取得之日开始认为可用，不把文件中的旧日期冒充当时已知的日期；后续修订保留版本。历史数据不足时，界面显示“次数不足，暂不判断”，不借用今天股息率制造过去的分数。可在该面板导入UTF-8 CSV：`date,dividend_yield,available_date`，并确认确实对应红利低波100及真实可用日期；5表示5%。日期不合法、未来可用日期或同一版本冲突会拒绝，整份校验通过后才保存。历史国债数据缺少盘中公布时间，统计中保守延后一个自然日使用；价格与估值仍按配置限制日期差。


## 指标参数怎么调

研究台的选股区、策略编辑区、K线区，以及回测、因子检验、机器学习和大盘页面都有“调整指标参数”。先选因子或指标，再展开填写计算周期、平滑条件或形态门槛。KDJ三线和MACD各线共用一组设置，避免同一组线采用不一致的参数。参数范围来自后端配置，非法周期关系会拒绝。

图表中修改后点“应用指标参数”重算；运行选股、检验或回测时会读取当前填写值。图表修改只改变观察指标，已有实验的成交记录保持原样。模板名中的20日、14日仍是原始名称，本次修改会在图表和报告另行列出。切换K线周期时，传统技术指标按所选K线计算；威科夫/道氏/背离等形态仍按日线及已完成周期识别。

将组合保存为自己的策略，可以同时保存指标参数、持仓与退出默认值。保存后的设置可用于下一次选股与回测。自定义公式的周期常数直接写在公式中，在因子管理里编辑；不把公式里的任意常数自动猜作可调参数。

所有新参数的标签、默认值、范围、共享关系及分页数量在 `config/research_controls.yaml.example`，需要全局修改时可创建同名 `.yaml`。单次网页调参会传入请求及实验归档，不改全局配置。

## 仓位和退出规则怎么设

在“运行回测”里设置“仓位与资金分配”和“个股退出规则”：

1. 总股票仓位上限60%、单股上限10%、最多选6只时，满足条件且有数据的股票各分10%；其余至少40%保留现金。只选到3只时不会强行把现金集中到这3只。
2. “波动较小的股票多分一些”使用信号日已知历史波动的倒数分配，再应用单股上限；历史不足或零波动不分配预算。
3. 止损、止盈、移动止损或最大持有期填0表示关闭。止损/止盈按含买佣金的成本计算；移动止损看持仓后的最高有效收盘。
4. 使用前一日收盘判断、次日开盘执行，遇到跳空按实际开盘和滑点成交。日内曾跌到门槛但收盘未触发，不会假定执行盘中止损。当天无法成交时保留退出请求；个股退出不同时调仓其他股票。
5. “暂停买回几天”从风险卖出后开始计，避免立刻重新买回。微调门槛只用于仍要保留的仓位；清仓或风险退出不受它阻挡。

仓位上限是调仓目标，之后价格变化、费用和无法卖出可能使实际比例暂时偏离。当前仍用前复权价和小数调整份额；完整日线筛查、整手、涨跌停、税率分段、公司行为等近似见报告，不能把它当成真实交易账户。

独立“仓位管理”可选择实验，查看截止日现金、股票仓位、成本、浮动盈亏、持有天数和等待执行的退出原因。旧实验缺少成本字段时留空，不倒推制造记录。下半页可以选择保存的股票池或输入完整代码，填写日期、资金和分配方式，计算研究预算；名单选出日不能晚于预算日期。预算不包含委托费，也不生成整手委托。

## 怎么核对一次实验

回测报告展开“本次参数、仓位规则与期末持仓”，核对指标周期、仓位、退出和交易费用。每次新实验保留代码/配置摘要、Python及主要依赖版本；原始行情版本未完整归档，行情更新后重新运行仍可能变化。

“用这次参数重新设置回测”把实验参数带回表单；“打开仓位管理”查看该次实验期末状态。成交明细中的股票按钮会定位到对应成交日K线，显示归档实际成交，研究识别信号另行标注。

回测、因子检验和模型训练使用后台任务。刷新同一浏览器标签页会恢复查看任务，不会重复提交。服务重启导致未完成的任务中断时会明确提示；修改参数后不能把另一份正在执行的任务当成本次结果。请求失败默认显示错误，不静默伪装成更新成功。

手机宽度下侧栏覆盖显示，正文保持全宽，表格在内部横向滚动。因子、策略和回测目录支持分页；回测比较的勾选跨页保留。对比先核对日期、股票范围、费用、指标设置及版本；回测表现好坏仍需独立区间和数据/成交规则验收。

项目范围、已处理项和下一步交易口径缺口见 [平台功能评审与修改清单](平台功能评审与修改清单.md)。


## 两种研究方式共用指标和数据

平台同时支持专业因子研究，以及“基本面＋技术面筛候选股，再等待技术条件”的流程。因子管理中的公式可用于画图、选股条件、入场退出条件；分组收益、RankIC、ICIR、衰减、自相关、机器学习和成本回测继续保留。预览几只股票只是检查公式是否按预期计算，不替代横截面检验或独立区间验证。

### 完善后的指标编写

打开“因子管理 → 编写自己的指标”：

1. 可以载入均线、均线金叉、RSI、量比或基本面条件示例，也可以展开“用条件组合生成公式”，选择指标/公式、比较方式和阈值，生成后继续编辑。
2. 支持 `MA(close,20)`、`EMA(close,20)`、`REF(close,1)`、`RSI(close,14)`、`CROSS(MA(close,5),MA(close,20))`、`COUNT(close>REF(close,1),5)`；仍支持原来的rank、相关性、时间序列函数和已有指标编号。
3. “检查公式”核对函数、参数数量、依赖与周期。周期须为正整数，不允许负周期引用未来；未知指标、循环依赖和任意Python代码会被拒绝。
4. 填1至10只完整代码、日期，点击“预览指标与数值”，查看K线、主图/副图和有效值数量。空值保留为空；横截面rank在单只股票上没有选股区分能力。
5. 填名称、编号、说明后保存，可以加入策略、在K线上叠加，或进入单因子检验。价格均线可选主图；RSI/量比/条件适合副图。条件公式大于0表示满足、0表示不满足，缺数时不判断。

预热长度会沿嵌套公式与指标依赖扩大。新因子检验同时保存所用定义、指标参数与代码依赖摘要，便于核对；仍须留意历史行情版本、样本选择和未实现的行业/市值控制。

### 从候选名单等到技术信号

入口是“候选股信号” `/signals`。先在研究台用基本面与技术面条件选股，保存股票池；手动名单也可使用。股票池只固定候选代码，不代表已经买入。

选择候选名单，载入或自己编写入场与退出条件，保存信号方案。方案保存候选池、公式和指标依赖快照，修改指标后可另存新方案。点击“检查收盘信号”，分别显示入场、退出、等待、买卖冲突、数据不足与行情过旧；每只股票可打开K线查看空心信号标记及两个条件副图。这里不写入实际持仓，也没有建立后台定时监控；更新行情后可再次手动检查。

“带入回测”会携带方案及股票池。回测按前收盘条件、下一交易日开盘尝试成交：有空位才新建仓，持仓等待技术退出或仓位页设置的风险退出，普通换股日不强制卖出。入场/退出同时满足时不新建仓；已有持仓优先技术退出。原选股策略用于空位候选排序与数据条件检查。名额不足、不能成交或冷静期内保留现金；有持仓退出时，释放的空位从下次检查再参与入场。固定名单不能用于确定日期之前，真实成交与形态信号分开显示。

这条流程与专业因子研究相互连接：可先检验一个因子，再把它加入候选筛选或技术条件，也可将观察到的技术条件回到因子页做横截面检验。

### 数据更新与补缺

“股票与数据”增加“检查并补齐日线缺口”，可限定代码、日期，也可对全部已下载股票检查：

- 使用AKShare新浪交易日历，失败时回退本地指数实际日期并明确来源；不把周一到周五直接当交易日。当天尚未结束的日线不检查。
- 检查OHLC、成交量、成交额和换手率的缺失/非法值；0成交量单独显示。未知历史ST不填成正常交易，2019年前换手率仍不用于结论。
- 依据已知上市日期排除上市前日期；没有上市日期时，首条记录以前标记为未核实，不能因此声称历史完整。“更新股票名称与代码”会同时尝试获取交易所来源的上市日期，失败保留原因。
- 补缺重新拉取有缺口股票的完整前复权窗口，尝试新浪、腾讯、东方财富。重叠OHLC一致时才合并缺字段；复权价格冲突会记录并跳过。读回本地缓存后再次检查，列出补回日期/字段及残留缺口。
- 缺日可能是停牌，多个来源都没有该日也不会捏造K线。上市/退市历史、停牌原因和历史ST仍需额外资料；检查报告中的“缺日待核对”不能直接等于下载漏数。
- 普通“更新股票日线”完成后自动执行上市日期获取、缺口检查及补缺；通过命令行可加 `--verify-gaps` 使用同样流程。续传还比对日线内容摘要，行数相同但内容改变时不会直接跳过。

检查结果写在本机 `output/research_data_quality.json`；交易日历为 `output/research_trade_calendar.json`；信号方案在本地SQLite中保存。它们均不随开源代码再分发行情。手动补缺与下载共用工作区写入锁；普通更新的下载、上市日期补充和后续补缺全程持有同一个写入锁，避免重复写入。检查与补缺任务会显示当前处理数量，页面刷新可恢复查看。
