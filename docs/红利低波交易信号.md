# 红利低波交易信号 v1

目标是输出可解释的“低位反转入场、上涨转弱退出”条件，同时区分信号、模拟持仓和实际成交。当前是实验性信号服务；未通过全新样本外验证，不承诺每轮低买高卖或达到特定收益。

## 使用方式

命令行和 HTTP API 使用同一后端。没有另建页面或第二套推荐算法。

```powershell
python -X utf8 scripts/dividend_signals.py --code 512890.SH
python -X utf8 scripts/dividend_signals.py --all --end 2026-10-29
python -X utf8 scripts/dividend_signals.py --code 515450.SH --profile kdj_21_5_filtered
```

本地 API：`GET /api/studio/signals/dividend?code=512890.SH&profile=kdj_21_5&end=2026-10-29&history=true`。

`code`、`profile`、`start`、`end`、`history` 为可用参数，未知参数报错，不静默忽略。日期结束不能晚于本机上海时区最近已收盘日期；日期省略时读取现有缓存到该日期，**不使用旧研究配置中的固定结束日假装当前数据**。不自动下载、不下单、不注册定时任务。

配置源是 `config/dividend_signals.yaml.example`；需要自定义时复制为被 Git 忽略的同名 `.yaml`。证券名称和资产基础信息复用 `dividend_timing_research`，观察范围、指标参数、状态名称由配置提供。可将已有基础资产配置中的长江电力等加入观察范围；新的资产还需基础资产配置、未复权行情和公司行为数据。

完整研究结果保存在配置的 `output_dir`，默认 `output/strategy_research/dividend_signals_v1/`。文件名包含证券、参数及输入哈希和请求日期，原始行情、完整账本和图形不提交 GitHub。

## 当前配置与规则

默认配置 `kdj_21_5` 保留用户最近查看的参数：21 日 RSV，K、D 都使用 `alpha=1/5` 的递推平滑，超卖/超买为 20/80；等价参数描述是 KDJ(21,5,5) 配阈值20/80。它是用户指定的观察配置，不是冻结选参胜出者。

- 买入条件：近5个观察交易日某日 K、D 同时不高于20；近3日出现金叉；当前 K>D，且连续信号口径收盘高于昨日。卖出条件同时成立时退出优先。
- KDJ退出：近5日某日 K、D 同时不低于80，当前死叉。
- 趋势退出：近10日曾站上MA10，连续2日收盘低于MA10，且MA10下降。两种退出条件满足任一种即可。
- 成交量在这个配置中不参与过滤。风险控制沿用基础执行配置，默认没有额外固定止损或移动止盈；不能把MA退出说成最大回撤保证。

可选 `kdj_21_5_filtered` 接入已存在的过滤适配器：保留低位KDJ确认，入场还要求MA20>MA60、MA60较5日前上升、价格不低于MA60的98%，近3日有量比至少0.8的记录。量比基线为当日之前20日平均成交量。退出为高位死叉或连续2日低于下降的MA10。这个适配器的MA退出没有“近10日曾站上”的前置条件，区别显式保留，不把两者当作同一个算法。

**过滤越多不代表越好**：2020-01-02至2026-10-29的现有缓存回放中，过滤配置对512890没有成交。它用于比较过滤影响，不替换默认配置；不能把空仓零回撤描述为稳定盈利。

配置 `risk` 可设置统一模拟器已经支持的 `stop_loss_pct`、`take_profit_pct`、`trailing_stop_pct`、`max_holding_days`、`risk_cooldown_days`；百分比单位和执行含义保持原模拟器约定。没有启用的风控不会被描述为已启用。风险退出和拒绝成交分别保留在 `trades[].trigger`、`rejections`，不伪装成技术卖出。

## 输出语义

|状态|含义|
|---|---|
|`buy`|模型空仓，已满足入场条件；不等于已经成交|
|`sell`|模型持仓，已满足技术退出条件|
|`hold`|模型持仓，未满足退出条件|
|`weakening`|模型持仓且低于退出均线，但完整退出条件尚未成立；仅观察|
|`setup`|模型空仓，最近到过超卖区，尚未确认入场|
|`wait`|模型空仓等待；空仓时持续满足退出条件不会反复给出卖单|
|`insufficient`|指标预热或必要输入不足|

`latest.state` 使用统一回测账本的当日收盘持仓。它不是用户真实账户；`if_flat` / `if_held` 同时给出两种实际持仓情形下的条件解释。`entry` / `exit` 保留原始条件，`reasons` 区分低位反转、高位死叉、MA退出和待确认。

信号在收盘确认，下一交易日开盘由统一模拟器尝试执行。一字板、费用、现金、冷却期等规则均继续生效。`fills` 是当天已发生的模拟成交，和当天收盘新条件属于不同时间；`next_scheduled_session` 只是参考日历中的下一交易日，不能理解为已成交日期。未找到参考日期时为 `null`，不用周一至周五猜交易日。

`history=true` 附带日状态、原价K线、映射回原价尺度的退出均线、真实账本权益/现金/应收分红和成交，供现有前端或外部客户端接入。`metrics`、`stress_metrics`、`buy_hold_metrics` 分别是相同资产、相同起止窗口的常规费用、压力费用和持续持有对照；从收益曲线计算的日胜率不能当作逐笔交易胜率。

## 分红、质量与证据边界

信号只向前应用当时已经发生的分红/拆分，历史数据不回写；成交使用未复权价格，登记、除息、支付和FIFO红利税仍由原现金账本处理，不把复权收益和现金分红重复相加。

既有基金/股票数据格式继续可读。新增证券可按 `config/dividend_cash_actions.json.example` 提供 `<六位代码>_cash_actions.json` 标准事件列表，放在基础配置的 `cash_actions_dir`。该标准文件存在时优先使用，必须包含该证券的全部已核验事件；不要只写补充事件，否则会覆盖旧格式的读取结果。列表可为空，但空列表本身不证明没有分红。

`quality` 同时暴露：

- `stale`：是否落后于请求日期对应的完整参考交易日历；缺少完整日历时为`null`，不冒充新鲜。
- `missing_sessions`：参考日历有而该证券没有的行情日期；可能停牌或数据缺口，保留待核对状态，不补造价格。
- `cash_actions.complete`：是否有显式公司行为核验记录覆盖数据末日。
- `data_ready`：以上条件合格、末日有成交量且指标可计算。这个字段只表示数据条件，不表示策略已验证有效。

公司行为完整性记录路径由 `action_coverage_file` 指定，格式参考 `config/dividend_action_coverage.json.example`。逐项核验原始公告、导入事件后，才可填写 `verified_through` 和来源；文件修改时间、最后一次分红日期不能代替核验。当前未自动生成这种声明。

截至本轮检查，本地两只ETF行情均截止2026-10-29；512890还有2021-10-22待核对缺日，公司行为完整性记录缺失。历史回放可用于开发和观察，当前数据不应被标成可直接用于当前交易。
