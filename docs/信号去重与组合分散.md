# 信号去重与组合分散

本次更新在现有 `raw_factor → factor_score → research_portfolio` 链路内增加信号去重和组合诊断。T+1、成交成本、一字行情过滤、交易间隔及原有退出规则沿用原实现；没有新增页面。旧归档不被修改，旧研究报告的收益也没有因本次改造而重新得到验证。

## 默认行为与兼容

`config/research_diversification.yaml.example` 是公开默认配置，可复制为本地 `config/research_diversification.yaml` 覆盖。配置查询：`GET /api/studio/diversification`。

- 普通 `factor_score` 和 `weighted_rank_composite` 默认自动去重：使用当日之前 120 个交易日的排名信号，至少 20 个有效日、60 个成对样本；绝对相关性大于 0.85 的项按权重优先、配置顺序次之剔除。负相关重复也会剔除；相关矩阵是按日期内股票排名、跨历史窗口汇总的 Pearson 相关。
- 初期历史不足默认保留信号并在审计字段中标记相关性未知；可设置 `unknown_policy: block` 严格限制。未知不等于低相关。
- 去重不删除原策略的显式上下限过滤条件。普通加权仍要求原条件有数据；允许部分因子缺失的复合算法继续使用有效权重分母。去重后的最低有效项数不超过保留项数。
- 通过 `signal.enabled: false` 可复现原始加权公式。默认开启会改变新运行的多因子得分，需重跑比较，不应直接沿用旧收益结论。该去重机制不是行业中性化或增量 IC 检验。
- 股票组合硬约束默认 `portfolio.enabled: false`，以兼容原策略。通过请求、保存策略或本地配置显式启用；行业/风格上限默认不设置。单因子去重无需开启硬约束。

## 选股与实际买入约束

原有 `POST /api/research/run`、`POST /api/research/screen` 接受额外的 `diversification` 对象；原有参数和返回字段保留。也可在 `POST /api/research/strategies` 的策略顶层保存该对象。后续请求可覆盖策略配置；未提供该字段的策略编辑会保留已保存的分散设置。

```json
{
  "strategy": "tech3",
  "start": "2024-01-01",
  "end": "2024-12-31",
  "diversification": {
    "signal": {"enabled": true, "max_abs_correlation": 0.85},
    "portfolio": {
      "enabled": true,
      "window": 120,
      "min_observations": 60,
      "max_abs_correlation": 0.8,
      "industry_cap": 0.3,
      "style_cap": null,
      "missing_policy": "block"
    }
  }
}
```

约束在目标仓位计算及实际买入前各检查一次。股票相关性来自信号日前的已知收盘收益，实际买入检查包含卖不出的旧持仓和当日已成交的新持仓；开盘价格仅用于可执行的份额与 NAV 预算计算。不通过的仓位保留现金，不补造独立标的、不自动放大剩余仓位。

约束属于建仓限制。价格漂移、相关性变化或停牌可能造成持有期超限；最终 `diversification.final.violations` 会报告超限，不额外更改原有退出或撮合规则。风险预算优先满足输入标的顺序，不宣称全局最优。旧研究脚本直接调用共享模拟器时，可通过参数 `diversification` 或面板 `_portfolio_policy` 显式启用。

## 行业和风格数据

行业从 `exposures.history_file` 指定 CSV 读取，默认本地路径 `data/private/exposure_history.csv`。文件不存在时标记未知；启用行业上限且 `missing_policy: block` 时，未知标的不能买入。不会抓取当前行业后回填历史。

CSV 必须包含以下字段：

```csv
code,dimension,bucket,valid_from,valid_to,available_date
SYN_A,industry,synthetic_group,2024-01-01,2024-12-31,2024-02-01
```

示例为合成证券。标签只在有效期内且到达 `available_date` 后使用；同一证券、同一维度的有效记录重叠会拒绝计算。记录需明确版本的有效区间，不能通过追加未来修订覆盖历史。支持 `style:名称` 的时点标签。真实分类文件和本地配置已加入忽略规则，不推送第三方数据。

默认风格维度为历史动量、历史波动率和市值的截面低/中/高组；市值需要提供同日 `cap`/`fund:cap` 面板或带日期的风格分类，否则显示未知。可在配置 `exposures.styles` 设置所需维度；它们是可解释代理，不等于完整 Barra 风格模型。行业/风格上限均是净资产权重，不是已投资资产内的相对权重。报告同时给出未知权重、最大组权重和已知投资部分的 HHI。

## 策略间比较与配置权重约束

`POST /api/studio/strategy-risk/compare` 读取本地统一回测归档，只截取截止日期之前的记录：

```json
{
  "archive_ids": ["research_strategy_a_runid", "research_strategy_b_runid"],
  "as_of": "2024-12-31",
  "weights": {"research_strategy_a_runid": 0.4, "research_strategy_b_runid": 0.4},
  "constraints": {
    "min_observations": 60,
    "max_strategy_weight": 0.4,
    "max_abs_return_correlation": 0.8,
    "max_signal_overlap": 0.8,
    "max_holding_overlap": 0.8,
    "industry_cap": 0.3,
    "missing_policy": "block"
  }
}
```

只允许安全且不重复的归档名称，不能传文件路径。按请求权重从高到低确定可配置权重，相关/重叠超限则拒绝加入，行业和风格超限则缩减额度，余额作为现金。暴露组合使用所有归档共同具备的最近账户日期，不将最后持仓倒推到更早日期。

诊断包含：

- 按共同交易日计算的策略收益相关性及样本数，缺失收益不补零；
- 同日候选代码集的 Jaccard 重叠率；空仓日、活跃日均值及最大值分别给出，硬约束使用活跃日均值；
- 实际持仓的 Jaccard 重叠及共享净资产权重 `sum(min(wA, wB))`；
- 组合行业和风格权重、策略权重 HHI、对齐日期的日波动与分散比率；
- 可配置权重、被拒原因和现金比例。

新回测的 `daily_account` 新增真实逐日持仓权重和暴露，另存 `signal_candidates` 和 `diversification` 审计结果。旧归档缺少信号或权重时返回 `unavailable`；严格缺失策略会拒绝未经核验的组合，不将未知当零重叠。候选信号是风险约束前的排名集合，实际成交后的持仓由账本另行记录。

`diagnostic_returns` 为用筛选后固定权重计算的历史统计，包含事后选择因素，不含组合层再平衡成本，不可当成可交易组合回测或未来收益证明。所有约束仅相对于截止日前的历史观测成立。

## 验证

```powershell
python -X utf8 -m unittest validation.test_diversification -v
python -X utf8 validation/run_diversification_smoke.py
python main.py validate
git diff --check
```

单测使用合成数据验证去重数学、未来扰动、时点分类、卖出失败、仓位预算、缺失记录和路径边界。HTTP smoke 使用现有本地缓存跑两个统一账本并调用比较 API，结果位于 `output/diversification_validation/`；该目录不会提交 GitHub。
